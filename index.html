Network Watch: a concept for traffic operators

A one-day design exercise built on the data model of Queensland's public traffic feed (QLDTraffic API v1.10): the same event types, priorities, lane impacts and timestamps the public feed uses. It is not STREAMS and not affiliated with Transport and Main Roads or Transmax. I have never seen an operator's screen, so every decision below is a hypothesis to test in a control room.

The question behind it

When something happens on the network, do operators start from the list or from the map? This concept bets on the list for priority, the map for context: the queue decides what you look at next, and the map follows your selection.

Design decisions

  • Unplanned first. Crashes, hazards, flooding and congestion sit in "Needs attention". Roadworks and special events are collapsed under "Planned", because they were scheduled and rarely need a response now.
  • Sorted by priority, then impact, then time. Red alert before high, blocked lanes before delays, newest first within a tie.
  • Never colour alone. Priority shows as a coloured stripe, a text label and the order in the list, so it still reads for colour-blind operators and on a washed-out wall screen.
  • Stale data is flagged. An unplanned event not updated in over an hour is marked, because an operator needs to know whether information is current before acting on it.
  • Keyboard first. Arrow keys move through the queue, Enter opens details, Esc closes, / searches. Operators on shift shouldn't need to aim a mouse.
  • Dark by default. Control rooms are dim and shifts are long. To check with operators, not assume.

What I'd want to learn from operators

  • In the first 60 seconds of a motorway crash, what do you look at, in what order?
  • What makes an event "yours": district, road, device, or whoever picks it up first?
  • How do you know an event is already being handled, or that its information is out of date?
  • What is on the wall screens versus your own desk, and do they ever disagree?
  • Which events do you ignore, and could the system learn that safely?

How it was made

Designed and built in a day with Claude Code, from the QLDTraffic API specification (v1.10) to a working prototype, then checked for keyboard use, screen-reader labels and phone layout.
